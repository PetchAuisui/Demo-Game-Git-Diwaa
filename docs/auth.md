# ระบบบัญชีผู้เล่น (Auth)

เอกสารนี้อธิบายระบบล็อกอิน / สมัคร / บัญชีผู้เล่นของ Git-Diwaa: ทำงานยังไง รันยังไง อะไรที่ยังไม่เสร็จ และอะไรที่ต้องระวังเรื่องความปลอดภัย

## ภาพรวม

```text
เกม (Godot, GDScript)                         server (C# ASP.NET Core, .NET 10)
───────────────────────                       ─────────────────────────────────
หน้าจอ (features/auth/*)                        /api/v1/accounts/*  (Accounts/AccountEndpoints.cs)
   │  เรียกผ่านทางเดียว                                │
   ▼                                               ▼
PlayerSession (common/player_session.gd)       AccountService (ตรวจกติกา, ตัดสินทุกอย่าง)
   │                                               │
   ▼                                               ▼
AuthApiClient (services/auth_api_client.gd) ──► Repository (ตอนนี้: เก็บในหน่วยความจำ)
```

หลักสำคัญ: **server เป็นผู้ตัดสินเสมอ** การตรวจในเกม (รูปแบบชื่อ รหัสผ่าน สิทธิ์เปลี่ยนชื่อ) มีไว้ช่วยผู้เล่นเท่านั้น ผู้เล่นแก้เกมหรือไฟล์ในเครื่องได้ทั้งหมด

### สถานะผู้เล่น (`PlayerSession.state`)

| สถานะ | ความหมาย | ใช้ฟีเจอร์ออนไลน์ได้ |
|---|---|---|
| `SIGNED_OUT` | ยังไม่มีผู้เล่น (อยู่หน้าล็อกอิน) | - |
| `ONLINE` | ล็อกอินแล้ว ติดต่อ server ได้ | ได้ |
| `OFFLINE` | ใช้บัญชีที่จดจำไว้ตอนติดต่อ server ไม่ได้ | ไม่ได้ |
| `GUEST` | เล่นโดยไม่ล็อกอิน ชื่ออยู่ในเครื่องเท่านั้น | ไม่ได้ |

### ไฟล์หลัก

| ไฟล์ | หน้าที่ |
|---|---|
| `game/common/player_session.gd` | autoload ตัวกลางของสถานะผู้เล่น ทุกหน้าใช้ผ่านตัวนี้ |
| `game/features/auth/auth_view.tscn` | หน้าแรกของเกม: ล็อกอิน / สมัคร / เล่นโดยไม่ล็อกอิน |
| `game/features/auth/account_menu.tscn` | ปุ่มรูปโปรไฟล์บนแถบบน + เมนู (จัดการบัญชี / ออกจากระบบ) |
| `game/features/auth/account_view.tscn` | หน้า "บัญชีของฉัน" แบบลอยทับ (เปลี่ยนชื่อในเกม / ตารางอันดับ) |
| `game/features/auth/player_avatar.tscn` | วงกลมรูปโปรไฟล์ ใช้ร่วมทุกที่ (แก้ที่นี่ที่เดียวถ้าจะเพิ่มรูป) |
| `game/features/auth/privacy_policy.gd` | เนื้อหานโยบายความเป็นส่วนตัว + `VERSION` |
| `game/features/auth/services/auth_config.gd` | ที่อยู่ server (`DEV_BASE_URL`, `RELEASE_BASE_URL`) |
| `game/features/auth/services/session_store.gd` | เก็บ "จดจำการเข้าสู่ระบบ" ลงไฟล์แบบเข้ารหัส |
| `server/src/GitDiwaa.Online/Accounts/` | กติกาและ contract ที่ใช้ร่วม (เช่น `AccountRules.cs`, `PrivacyPolicy.cs`) |
| `server/src/GitDiwaa.Server/` | ตัว server: endpoint, service, ความปลอดภัย, repository |

## วิธีรัน

ต้องมี .NET SDK 10 (เฉพาะคนที่จะรัน server) ส่วนเกมใช้ Godot 4.7.2 ตามปกติ

```powershell
# รัน server (ฟังที่ http://127.0.0.1:5280 ตรงกับ DEV_BASE_URL ในเกม)
cd server
dotnet run --project src/GitDiwaa.Server

# รันเทส (ปิด server ก่อน ไม่งั้น build ไม่ผ่านเพราะไฟล์ถูกล็อก)
dotnet run --project tests/GitDiwaa.Online.Tests
dotnet run --project tests/GitDiwaa.Server.Tests
```

ทดสอบ rate limit ง่ายๆ: เปิด server ด้วย `-- --RateLimit:AuthPermitLimit=2`

ตอนรันแบบ Development (`dotnet run` ปกติ) server **ไม่กันรหัสผ่านอ่อน** ให้ทีมใช้ `12345678` ทดสอบได้ ถ้าอยากลองแบบตอนปล่อยจริง ใส่ `-- --Accounts:RejectWeakPasswords=true`

ข้อควรรู้ตอนพัฒนา:

- ข้อมูลบัญชีอยู่ในหน่วยความจำ **ปิด server แล้วบัญชีหายหมด** (จะแก้ใน PR ฐานข้อมูล)
- Godot รุ่น mono แก้ `game/project.godot` เองทุกครั้งที่เปิด ให้ `git restore game/project.godot` ก่อน commit เสมอ
- หน้าแรกของเกม (`run/main_scene`) คือหน้าล็อกอิน ถ้าล็อกอินค้างไว้จะพาเข้าหน้าเริ่มเอง

## API (สรุป)

ทุก endpoint อยู่ใต้ `/api/v1/accounts` ตอบเป็น JSON error มีรูปแบบ `{"code": "...", "fieldErrors": [...]}`

| Method | Path | ต้อง login | หมายเหตุ |
|---|---|---|---|
| POST | `/register` | - | สมัคร ชื่อในเกมตั้งให้เป็น `player-<เลข>` (เริ่ม 10001) |
| POST | `/register/check` | - | ตรวจชื่อผู้ใช้ / อีเมลซ้ำก่อนเปิดหน้านโยบาย ไม่บอกว่าช่องไหนซ้ำ |
| POST | `/login` | - | ล็อกอินด้วยชื่อผู้ใช้หรืออีเมล |
| POST | `/refresh` | token | ต่ออายุ token (หมุน token ใหม่ทุกครั้ง ใบเก่าต่ออายุซ้ำได้อีก 60 วินาที ถ้าใบใหม่ยังไม่ถูกใช้) |
| POST | `/logout` | token | ยกเลิก token (โควตาเดียวกับ `/me/*`) |
| GET | `/me` | token | โปรไฟล์ (ไม่มีอีเมล) |
| GET | `/me/email` | token | อีเมลของตัวเอง (เมนูแสดงแบบปิดบัง) |
| GET / PATCH | `/me/display-name` | token | สิทธิ์เปลี่ยนชื่อ / เปลี่ยนชื่อในเกม |
| GET / PUT | `/me/leaderboard-consent` | token | ความยินยอมขึ้นตารางอันดับ |
| GET | `/health` (นอก group) | - | เช็คว่า server ยังอยู่ |

กติกาสำคัญ:

- เปลี่ยนชื่อในเกมได้ 2 ครั้งแรกฟรี ใช้หมดแล้วได้คืน 1 ครั้งทุก 14 วัน (สะสมไม่ได้)
- ชื่อรูปแบบ `player-<ตัวเลข>` สงวนไว้ให้ระบบ
- ใส่รหัสผิด 5 ครั้งจาก IP เดียวกัน พักการล็อกอินของ IP นั้นกับบัญชีนั้น 15 นาที (คนอื่นแกล้งล็อกบัญชีเราจากเน็ตอื่นไม่ได้) และถ้าใส่ผิดรวมกันจากทุก IP ครบ 20 ครั้ง พักทั้งบัญชี 15 นาที (กันการเดารหัสโดยสลับ IP) ตัวนับทั้งสองแบบเริ่มนับใหม่เมื่อครั้งล่าสุดห่างเกิน 15 นาที และอยู่ใน repository แบบ atomic ยิงพร้อมกันก็นับครบ
- **สาย token**: ล็อกอิน 1 ครั้ง = 1 สาย (`SessionRecord.FamilyId`) ทุกใบที่ได้จากการต่ออายุต่อกันมาอยู่สายเดียวกัน ล็อกอินจากอีกเครื่องเป็นอีกสาย เมื่อพบใบเก่าถูกใช้ซ้ำ server **ตัดทั้งสายของเครื่องนั้น** เท่านั้น เครื่องอื่นของบัญชีเดียวกันไม่กระทบ (`RevokeAllForUserAsync` ที่ตัดทุกเครื่องยังอยู่ เก็บไว้ใช้ตอนเปลี่ยนรหัสผ่าน)
- token อายุ 12 ชั่วโมง (ติ๊ก "จดจำ" = 30 วัน) ระหว่างเล่นเกมต่ออายุให้เองเมื่อเหลือไม่ถึง 30 นาที (ตอนจะส่งคำขอที่ใช้ token) ถ้า server ไม่รับ token แล้ว เกมเปลี่ยนเป็นออฟไลน์และบอกให้เข้าสู่ระบบใหม่ (`PlayerSession.session_expired`)
  - เปิดเกม 2 หน้าต่าง (ใช้ไฟล์จดจำเดียวกัน): ก่อนต่ออายุ และเมื่อเจอ 401 เกมอ่านไฟล์จดจำก่อน ถ้าอีกหน้าต่างต่ออายุไปแล้ว (มี token ใบอื่นของบัญชีเดียวกันที่หมดอายุช้ากว่า) ใช้ใบนั้นเลย (กรณี 401 ส่งคำขอซ้ำ 1 ครั้งด้วยใบนั้น) และตอนทิ้ง token เกมลบไฟล์เฉพาะเมื่อในไฟล์เป็นใบเดียวกับที่ถืออยู่ ไม่ลบใบใหม่ของอีกหน้าต่าง
  - นาฬิกาเครื่องบอกว่าหมดอายุแล้วก็ยังลองต่ออายุ ให้ server ตัดสิน และไม่ลองถี่กว่า 5 นาที
  - คำขอต่ออายุที่ **อาจไปถึง server แล้วแต่คำตอบหาย** (หมดเวลารอ / การเชื่อมต่อหลุด / ได้ 5xx / อ่านคำตอบไม่ได้ = `AuthApiResult.maybe_delivered`): เกมลองใหม่ทันที 1 ครั้ง ถ้ายังไม่สำเร็จ
    - ระหว่างเล่น: ทิ้ง token แล้วเป็นออฟไลน์ ("ต้องเข้าสู่ระบบใหม่") เพราะ server อาจเปลี่ยน token ไปแล้ว **ตั้งใจให้เป็นแบบนี้**: เน็ตหลุดแบบเงียบ (แพ็กเก็ตหาย ไม่มีคำตอบ) ตอน token ใกล้หมดอายุ = เกมทิ้ง token ให้ล็อกอินใหม่ แม้คำขออาจไม่เคยถึง server เลยก็ตาม
    - ตอนเปิดเกม: ไม่ล้างไฟล์จดจำ ขึ้น "เชื่อมต่อ server ไม่ได้" และเล่นออฟไลน์ได้ ถ้าครั้งหน้า token ในไฟล์ใช้ไม่ได้แล้ว server ตัดแค่สายของเครื่องนี้ แล้วเกมถามล็อกอินใหม่
  - คำขอที่ไปไม่ถึงแน่ๆ (ต่อไม่ติด / หาชื่อไม่เจอ / TLS ไม่ผ่าน) หรือถูกจำกัดจำนวนครั้ง: token ใบเดิมยังใช้ได้ เก็บไว้ตามเดิม
- ช่วงผ่อนผันหลังหมุน token (`AccountOptions.RefreshReuseGracePeriod` = 60 วินาที) มีไว้กรณีเดียว: **คำตอบ refresh หายกลางทางแล้วเกมลองใหม่** ใบเก่าใช้ **ต่ออายุซ้ำ** ได้เฉพาะเมื่อครบทุกข้อ
  - ใบเก่าถูกยกเลิกเพราะถูกหมุน (ไม่ใช่ logout) และหมุนมาไม่เกิน 60 วินาที
  - ใบใหม่ที่มาแทนยังใช้ได้อยู่ และ **ยังไม่เคยถูกใช้เลย** (ยังไม่ถูกใช้ = คำตอบอาจหายกลางทางจริง / ถูกใช้แล้ว = เจ้าของได้ใบใหม่แล้ว คนที่เอาใบเก่ามาคือคนขโมย)
  - ทุกครั้งที่ผ่อนผัน server ยกเลิกใบที่มาแทนก่อนหน้า แล้วให้ใบเก่าชี้ไปที่ใบใหม่ ในขั้นตอนเดียว: **ใบเก่า 1 ใบ มี session ที่ใช้ได้จากการผ่อนผันแค่ใบเดียวเสมอ** ยิงใบเก่าซ้ำกี่ครั้งก็ไม่ได้ session เพิ่ม และพอเจ้าของใช้ใบที่ได้ ใบเก่าจะต่ออายุไม่ได้อีก
  - ไม่ครบข้อใดข้อหนึ่ง = ถือว่าถูกขโมย ตัดทั้งสายของเครื่องนั้น ใบเก่าใช้เรียก `/me/*` ไม่ได้ตั้งแต่ถูกหมุน
  - เปิดเกม 2 หน้าต่าง **ไม่ได้อาศัยช่วงผ่อนผัน**: รองรับด้วยการที่เกมอ่าน token จากไฟล์จดจำก่อนต่ออายุและเมื่อเจอ 401 (ดูข้อ token ด้านบน)
  - **ช่องที่ยังเหลือ**
    - คนที่ขโมยใบเก่าแล้วยิงก่อนที่ใบใหม่จะถูกใช้ครั้งแรก ยังได้ session โดยไม่ถูกจับ (ใบของเจ้าของจะถูกยกเลิก เจ้าของจึงหลุดและต้องล็อกอินใหม่) ปิดไม่ได้ตราบที่มีการผ่อนผัน ถ้ารับไม่ได้ให้ตั้ง `RefreshReuseGracePeriod` เป็นศูนย์ (ใช้ใบเก่าซ้ำ = ตัดทันที แต่คำตอบหายครั้งเดียวผู้เล่นต้องล็อกอินใหม่ที่เครื่องนั้น)
    - เกม 2 หน้าต่าง refresh ใบเดียวกันพร้อมกันพอดี (ก่อนที่อีกหน้าต่างจะบันทึกไฟล์ทัน): ได้คำตอบสำเร็จทั้งคู่ แต่ใช้ได้แค่ใบล่าสุด อีกหน้าต่างจะหลุดเป็น "ต้องเข้าสู่ระบบใหม่"
- `/logout` ด้วย token ที่ถูกหมุนไปแล้ว (เกมถือใบเก่าเพราะคำตอบหาย) จะยกเลิกใบที่มาแทนตามสายไปจนถึงใบล่าสุดด้วย (ไม่เกิน 32 ขั้น)
- hash รหัสผ่าน (PBKDF2) ทำพร้อมกันได้ไม่เกิน (จำนวน core - 1) อย่างน้อย 1 ที่เหลือรอคิว เหลือ 1 core ไว้ให้คำขออื่นเสมอ
- rate limit (ตั้งใหม่ได้ใน appsettings / command line ที่ `RateLimit:*`):
  - endpoint ที่ไม่ต้องล็อกอิน (สมัคร / ตรวจซ้ำ / ล็อกอิน / ต่ออายุ) 60 ครั้ง/นาที ต่อ IP (`AuthPermitLimit`)
  - endpoint `/me/*` และ `/logout` 60 ครั้ง/นาที ต่อ session (`AccountPermitLimit`) ผู้เล่นในเน็ตเดียวกันไม่แย่งกัน
  - ทุกคำขอรวมกัน 300 ครั้ง/นาที ต่อ IP (`GlobalPermitLimit`)
- รหัสผ่านต้องไม่เดาง่าย: ไม่อยู่ในรายการยอดนิยม (`CommonPasswords.cs`), ไม่ใช่ตัวเดียวซ้ำ / ช่องว่างล้วน, ไม่เหมือนชื่อผู้ใช้หรืออีเมล (ปิดเองตอน Development)
- `PrivacyPolicy.VERSION` (เกม) ต้องตรงกับ `PrivacyPolicy.CurrentVersion` (server) แก้นโยบายเมื่อไหร่ต้องเปลี่ยนทั้งสองที่

## ต้องทำก่อนเปิดให้คนทั่วไปเล่น

ตอนนี้ระบบใช้ทดสอบภายในทีมได้ แต่ **ยังไม่พร้อมให้คนทั่วไปใช้** จนกว่าจะทำรายการนี้ครบ

| เรื่อง | ทำไม | อยู่ที่ |
|---|---|---|
| ฐานข้อมูลจริง (PostgreSQL) | ตอนนี้ปิด server แล้วบัญชีหาย (server จึงไม่เริ่มนอกโหมด Development ถ้าไม่ตั้ง `Persistence:AllowInMemory=true`) | PR ฐานข้อมูล |
| กันแกล้งล็อกบัญชี (device cookie) | ใส่รหัสผิด 5 ครั้งจาก IP เดียว พักบัญชีนั้นจาก IP นั้น / ผิดรวม 20 ครั้งจากหลาย IP พักทั้งบัญชี ในห้องเรียนที่ออก IP เดียวกัน หรือคนที่มีหลาย IP จึงแกล้งให้เจ้าของล็อกอินไม่ได้ได้ และยังไม่มีตัวนับผิดต่อ IP รวมทุกบัญชี แผน: device cookie ตามแนวทาง OWASP เครื่องที่เคยล็อกอินบัญชีนี้สำเร็จไม่โดนพักเพราะคนอื่นใส่ผิด ตัวนับต่อ IP ข้ามบัญชีนับเฉพาะเครื่องที่ไม่มีตรา (ต้องเก็บตัวนับที่ server เลยทำพร้อมฐานข้อมูล) | PR ฐานข้อมูล |
| สร้างผู้ใช้ + บันทึกความยินยอมใน transaction เดียว | ตอนนี้บันทึกแยกกัน ในหน่วยความจำไม่ล้ม แต่ฐานข้อมูลจริงถ้าบันทึกความยินยอมล้ม บัญชีจะมีอยู่โดยไม่มีหลักฐานความยินยอม | PR ฐานข้อมูล |

### เรื่องอายุ (ตัดสินใจแล้ว แต่ควรรู้)

ตอนสมัครใช้ช่องติ๊ก "ฉันมีอายุ 20 ปีขึ้นไป" (ผู้เล่นยืนยันเอง) แทนการถามปีเกิด เพื่อให้ใช้ง่าย 
ถ้าต้องจริงจังเรื่องนี้ ให้กลับมาทบทวน: ถามปีเกิดแบบเก็บในเครื่อง, server บันทึกว่ายืนยันอายุแล้ว, และขั้นตอนเมื่อพบว่าเป็นผู้เยาว์ (นโยบายเขียนไว้แล้วว่าจะระงับบัญชีและลบข้อมูล)

## สิ่งที่ตั้งใจออกแบบไว้ (อย่าเผลอแก้กลับ)

- **ข้อความ error ไม่บอกว่าบัญชีไหนมีอยู่จริง**: ล็อกอินผิดตอบเหมือนกันทุกกรณี, สมัคร/ตรวจซ้ำตอบแค่ "ชื่อผู้ใช้หรืออีเมลนี้ถูกใช้แล้ว"
- **ไม่แสดงชื่อผู้ใช้** ในเมนู / หน้าบัญชี และ **อีเมลปิดบังเป็นค่าเริ่มต้น** (กันหลุดตอนสตรีม / แคปจอ)
- **ไม่เอาข้อความดิบจาก server ไปแสดง** ข้อความบนจอเขียนเองในเกมทั้งหมด และใช้ `Label` ธรรมดา (ไม่ใช่ RichTextLabel)
- **ห้าม print token** token อยู่ใน `PlayerSession` เท่านั้น
- **เก็บ token ใบใหม่เสมอหลัง refresh** แม้ผู้เล่นจะเลือกเล่นแบบอื่นไปแล้ว ถ้าใช้ token ใบเก่าซ้ำหลังพ้นช่วงผ่อนผัน 60 วินาที หรือหลังจากใบใหม่ถูกใช้ไปแล้ว server จะถือว่าถูกขโมยและตัดทั้งสายของเครื่องนั้น
- **ไม่ใช้ token ที่ไม่รู้ว่ายังใช้ได้ไหมต่อระหว่างเล่น** ต่ออายุแล้วคำตอบหาย (ลองใหม่ 1 ครั้งแล้วก็ยังไม่รู้ผล) เกมทิ้ง token ใบเก่าทันที ยอมให้ผู้เล่นล็อกอินใหม่ รวมถึงตอนเน็ตหลุดแบบเงียบ (ตั้งใจ) ส่วนตอนเปิดเกมจะเก็บไฟล์จดจำไว้ให้เล่นออฟไลน์ได้ เพราะ server ตัดแค่สายของเครื่องนี้ ไม่กระทบเครื่องอื่น
- **ไม่ต่ออายุ token เมื่อเจอ 401** เกมต่ออายุล่วงหน้าตอนใกล้หมดอายุเท่านั้น เพราะ token ที่ถูกยกเลิกแล้วเอาไปต่ออายุจะเข้าเงื่อนไขถูกขโมย เจอ 401 = ดูไฟล์จดจำว่ามีใบใหม่จากอีกหน้าต่างไหม (มี = ส่งซ้ำ 1 ครั้ง) ไม่มีหรือยัง 401 = ทิ้ง token แล้วเป็นออฟไลน์
- **ความยินยอมตารางอันดับ** แสดงค่าจริงจาก server เท่านั้น โหลดไม่ได้ห้ามให้กด และถอนได้ง่ายเท่ากับให้
- **หน้าที่ออกแล้วเสียความคืบหน้า** (หน้าเล่นด่าน) ถามยืนยันก่อนออกจากระบบ / กลับหน้าหลัก

## เช็คลิสต์รีวิวความปลอดภัย

ใช้ตอนรีวิว PR (คนหรือ AI ก็ได้) ให้รีวิวทีละกลุ่มไฟล์ อย่าส่งทั้ง PR ทีเดียว

**รหัสผ่าน** (`server/src/GitDiwaa.Server/Security/PasswordHasher.cs`)
- [ ] ใช้ PBKDF2-SHA256 + salt สุ่มต่อคน, รอบ 600,000, เทียบผลแบบเวลาคงที่
- [ ] ไม่มีรหัสผ่านหลุดลง log / response / exception message
- [ ] record ที่มีรหัสผ่านหรืออีเมลซ่อนค่าใน `ToString` (`PrintMembers`)

**token / session** (`Security/SessionTokenService.cs`, `Accounts/AccountService.cs`)
- [ ] token สุ่ม 32 byte ด้วย `RandomNumberGenerator`, server เก็บแค่ hash
- [ ] refresh หมุน token ทุกครั้ง และใช้ token เก่าซ้ำหลังช่วงผ่อนผัน / หลังใบใหม่ถูกใช้แล้ว / หลัง logout = ยกเลิกทั้งสายของเครื่องนั้น (เครื่องอื่นไม่กระทบ)
- [ ] ทุก endpoint `/me/*` ผ่าน `RequireSessionFilter` และใช้ user id จาก session เท่านั้น (ไม่รับ id จาก request)
- [ ] เกม: token ไม่ถูก print, ไฟล์จดจำเข้ารหัส, ตรวจรูปแบบ token ก่อนใส่ header (กัน header injection)

**การไล่เช็คบัญชี (enumeration) และการเดารหัส**
- [ ] ข้อความตอบ login / register / register-check ไม่บอกว่าช่องไหนผิดหรือซ้ำ (ยังเช็คได้ว่าอีเมลมีบัญชีไหม ยอมรับไว้ก่อน ดูตารางด้านบน)
- [ ] `/register/check` ค้นทั้งชื่อผู้ใช้และอีเมลทุกครั้ง (เวลาไม่บอกใบ้)
- [ ] rate limit ครอบทุก endpoint บัญชี (ไม่ต้องล็อกอิน: ต่อ IP / `/me/*`: ต่อ session) และ lockout หลังใส่ผิด 5 ครั้งต่อ IP / 20 ครั้งต่อบัญชี (นับแบบ atomic)
- [ ] กันรหัสผ่านอ่อนเปิดอยู่เมื่อไม่ใช่ Development และข้อความ error ไม่สะท้อนรหัสผ่านกลับไป
- [ ] คำขอไป server เข้าคิว ไม่ถูกทิ้ง (โดยเฉพาะ `/logout`) ดู `AuthApiClient._send`

**ข้อมูลส่วนบุคคล**
- [ ] อีเมลส่งออกที่ `/me/email` ที่เดียว (มี `Cache-Control: no-store`)
- [ ] ไม่มีอีเมลใน `/me`, response ของ login / register และ log
- [ ] เกมไม่บันทึกอีเมลลงไฟล์

**ฝั่งเกม**
- [ ] ทุกอย่างที่ใช้ token คุยกับ server ผ่าน `PlayerSession` เท่านั้น (หน้าล็อกอินมี `AuthApiClient` ของตัวเองได้ เพราะส่งแค่คำขอที่ไม่ใช้ token: health / login / register / register-check)
- [ ] ข้อความจาก server ไม่ถูกแสดงตรงๆ บนจอ
- [ ] คำตอบที่มาช้า (หลังผู้เล่นเปลี่ยนหน้า / ออกจากระบบ) ถูกทิ้ง ไม่เขียนทับสถานะ

## การตัดสินใจที่ยังค้าง (ต้องคุยกับทีม)

- **แกล้งล็อกบัญชี**: ตกลงทำ device cookie ใน PR ฐานข้อมูล (ดูตารางด้านบน) ระหว่างนี้คนที่ติ๊ก "จดจำ" ไว้ไม่กระทบ เพราะเข้าด้วยการต่ออายุ token และไม่บอกผู้เล่นตรงๆ ว่า "บัญชีถูกพัก" เพราะจะบอกใบ้ว่าบัญชีนั้นมีอยู่จริง ข้อความล็อกอินผิดบอกกติกาการพักไว้แล้ว
- **ความคืบหน้าแยกตามผู้เล่น** (ข้อเสนอ ยังไม่ได้ทำ เพราะเป็นไฟล์ของเจ้าของระบบเซฟ):
  - `game/common/game_progress_manager.gd`: เปลี่ยน `SAVE_PATH` เป็น `user://saves/<slot>/game_progress.cfg` โดย `<slot>` = `PlayerSession.get_save_slot()` (`user_<id>` หรือ `guest`), ล้าง `_cached_cfg` ทุกครั้งที่ `PlayerSession.session_changed`, ย้ายไฟล์เซฟเดิมเข้า slot แรกที่เข้ามาเล่น และให้ระบบสำรองไฟล์เซฟเสียใช้ path ใหม่ด้วย
  - `game/features/sandbox/services/real_git_sandbox_service.gd`: เปลี่ยน `user://git-workspaces` เป็น `user://git-workspaces/<slot>`
  - `get_save_slot()` ตรวจ id ให้เป็น GUID อยู่แล้ว (กัน id ที่ถูกแก้เป็น `../..` พาไปเขียนนอกโฟลเดอร์)
  - guest ทุกคนในเครื่องเดียวกันใช้ slot `guest` ร่วมกัน (guest ไม่มีตัวตนให้แยก)
- **รูปโปรไฟล์**: ถ้าทำแบบอัปโหลด ให้ server วาดรูปใหม่เป็น 256×256 PNG ทุกครั้ง (ล้างไฟล์อันตราย / GPS) และเก็บในฐานข้อมูลตารางแยกก่อน ส่งให้เกมผ่าน endpoint เท่านั้น ฝั่งเกมแก้ที่ `player_avatar.gd` ที่เดียว
