# มาตรฐาน Responsive, ระบบ Navbar และการจัดการหน้าต่าง (Responsive & UI System Guide)

เอกสารนี้รวบรวมรายละเอียดการปรับแต่งระบบ Responsive, การควบคุมหน้าต่างเกมบนเครื่องคอมพิวเตอร์, การแก้ไขสัดส่วนและระยะห่างของแถบนำทาง (Navbar), และการทำงานของระบบสุ่มสีหมวกประจำเซสชันในเกม **GIT DI WAA**

---

## 1. การแก้ไขบั๊กระยะห่าง Navbar (Brand Button Spacing Bugfix)

### 1.1 ปัญหาที่พบ (Problem)
ในแถบนำทางด้านบน (Navbar) เกิดช่องว่างขนาดใหญ่ที่ผิดปกติระหว่างข้อความชื่อเกม **`GIT DI WAA`** กับเส้นขีดคั่นแนวตั้ง **`|`** ทำให้ดูแหว่งและไม่สมดุล เมื่อเทียบกับระยะห่างระหว่างเส้นขีดคั่นกับป้ายชื่อหน้า (เช่น `TOWER ROADMAP`, `SANDBOX`, `MAIN CONSOLE`, `DRESSING ROOM`)

```text
[ก่อนแก้ไข - ระยะห่างผิดปกติ]
[หมวก] GIT DI WAA                |   TOWER ROADMAP
      |<------- 53 px --------->|<- 16 px ->|

[หลังแก้ไข - สมมาตรสวยงาม]
[หมวก] GIT DI WAA    |   TOWER ROADMAP
      |<-- 17 px -->|<- 16 px ->|
```

### 1.2 สาเหตุเชิงลึก (Root Cause)
1. ตัวอักษร `GIT DI WAA` ใช้ฟอนต์ `Bungee-Regular.ttf` ขนาด 26px วัดความกว้างจริงของตัวอักษรได้ **157 px**
2. ข้อความถูกวางเยื้องจากขอบซ้ายของปุ่มแบรนด์ (`BrandBtn`) ด้วย `offset_left = 16.0` ทำให้ข้อความสิ้นสุดที่พิกัด `x = 173 px`
3. เดิม `BrandBtn` ถูกตั้งค่าความกว้างขั้นต่ำไว้เกินจริงที่ `custom_minimum_size = Vector2(210, 48)` ทำให้เกิดพื้นที่ว่างเปล่าที่มองไม่เห็นภายในปุ่มด้านขวาถึง **37 px** (`210 - 173 = 37`)
4. เมื่อรวมกับระยะห่างระหว่าง Element (`separation = 16 px`) ของ `HBoxContainer` ทำให้ระยะห่างจริงจากตัวหนังสือถึงเส้นขีดคั่นกลายเป็น **53 px** (`37 + 16`) ในขณะที่ฝั่งขวาของเส้นคั่นห่างเพียง **16 px**

### 1.3 วิธีการแก้ไข (Solution)
ปรับขนาดของ `BrandBtn` และขอบเขตของ Label ให้พอดีกับตัวอักษรที่เรนเดอร์จริงคือ **174 px** ในทุก Scene ที่มี Navbar:

| ไฟล์ Scene | โหนดที่แก้ไข | ค่าเดิม | ค่าที่แก้ไขใหม่ |
|---|---|---|---|
| `features/level_select/level_select_view.tscn` | `BrandBtn`<br>`BrandTitle` | `custom_minimum_size = Vector2(210, 48)`<br>`offset_right = 205.0` | `custom_minimum_size = Vector2(174, 48)`<br>`offset_right = 174.0` |
| `features/sandbox/top_bar_panel.tscn` | `BrandBtn`<br>`BrandLabel` | `custom_minimum_size = Vector2(210, 48)`<br>`offset_right = 205.0` | `custom_minimum_size = Vector2(174, 48)`<br>`offset_right = 174.0` |
| `features/start/start_top_bar.tscn` | `BrandBtn`<br>`BrandTitle` | `custom_minimum_size = Vector2(210, 48)`<br>`offset_right = 205.0` | `custom_minimum_size = Vector2(174, 48)`<br>`offset_right = 174.0` |
| `features/start/dressing_room_view.tscn` | `BrandBtn`<br>`BrandTitle` | `custom_minimum_size = Vector2(210, 48)`<br>`offset_right = 205.0` | `custom_minimum_size = Vector2(174, 48)`<br>`offset_right = 174.0` |

## 2. ระบบสุ่มสีหมวกแม่มดประจำเซสชัน (Session Hat Color Randomization)

### 2.1 ปัญหาที่พบ (Problem)
หมวกแม่มดบนตัวอักษร 'G' ใน Navbar เปลี่ยนสีสุ่มไปเรื่อย ๆ ทุกครั้งที่ผู้เล่นสลับหน้าจอ (เช่น จากหน้าแรก ➔ เลือกด่าน ➔ ย้อนกลับหน้าแรก หมวกเปลี่ยนสีตลอดเวลา)

### 2.2 สาเหตุเชิงลึก (Root Cause)
1. **ลำดับการประมวลผลของ Godot (Node Lifecycle):** โหนดลูกจะเข้าสู่สถานะ `_ready()` ก่อนโหนดแม่ ในหน้าจอหลัก `start_view.tscn`:
   - โหนดลูก `TopBar` จะรัน `_ready()` ก่อน และเรียก `GameProgressManager.get_current_hat_texture()` ซึ่งทำการสุ่มสีแรก (เช่น สีม่วง) และนำมาแสดงผล
   - จากนั้นโหนดแม่ `StartViewController` รัน `_ready()` ซึ่งมีโค้ด `GameProgressManager.randomize_hat_color()` สั่งสุ่มสีทับทันที (เช่น เปลี่ยนเป็นสีเขียว)
   - ผลลัพธ์: หน้าจอแรกแสดงสีม่วง แต่หน่วยความจำระบบกลายเป็นสีเขียว พอคลิกไปหน้าเลือกด่าน หน้าเลือกด่านจึงแสดงสีเขียว ทำให้ดูเหมือนหมวกเปลี่ยนสีตอนสลับหน้า
2. **การสุ่มซ้ำเมื่อย้อนกลับ:** เมื่อใดก็ตามที่กดย้อนกลับมายัง `start_view.tscn` โค้ดใน `_ready()` ของหน้าเริ่มเกมจะรันใหม่และสุ่มสีใหม่อีกครั้งเสมอ

### 2.3 วิธีการแก้ไข (Solution)
1. นำคำสั่ง `GameProgressManager.randomize_hat_color()` ออกจาก `_ready()` ของ `features/start/start_view_controller.gd`
2. ให้ `GameProgressManager` รับผิดชอบการสุ่มแบบ **Lazy Initialization** กล่าวคือ เมื่อเริ่มเปิดเกม ค่า `_current_hat_color` จะเริ่มต้นที่ `-1` และจะทำการสุ่มสีเพียง **ครั้งเดียวเท่านั้น** เมื่อมีการเรียกใช้งานครั้งแรก:

```gdscript
# common/game_progress_manager.gd
static var _current_hat_color: int = -1

static func randomize_hat_color() -> int:
	_current_hat_color = randi() % 3
	return _current_hat_color

static func get_current_hat_color() -> int:
	if _current_hat_color < 0:
		randomize_hat_color()
	return _current_hat_color
```

ผลลัพธ์: หมวกจะสุ่ม 1 ครั้งเมื่อเปิดเกม และคงสีเดิมไว้ตลอดทั้งเซสชัน ไม่ว่าจะสลับไปหน้าเลือกด่าน, ห้องแต่งตัว, หน้าทดลองเล่น หรือย้อนกลับมาหน้าหลัก

## 3. ระบบ Responsive และการแสดงผลหน้าต่างคอมพิวเตอร์ (Desktop Responsive System)

### 3.1 การตั้งค่าหน้าจอหลัก (Project Display Settings)
อ้างอิงจาก `game/project.godot`:

```ini
[display]
window/size/viewport_width=1920
window/size/viewport_height=1080
window/size/mode=3
window/size/window_width_override=1920
window/size/window_height_override=1080
window/size/resizable=true
window/stretch/mode="canvas_items"
window/stretch/aspect="keep"
window/stretch/scale_mode="fractional"
```

* **`stretch/mode = "canvas_items"`:** องค์ประกอบภาพ 2D และ UI ทั้งหมดจะคงความคมชัดตามพิกเซล และข้อความจะถูกเรนเดอร์แบบ Sub-pixel คมชัดทุกขนาดหน้าจอ
* **`stretch/aspect = "keep"`:** รักษาสัดส่วน 16:9 สเกลเต็มจออัตโนมัติบนจอทุกความละเอียด (เช่น 4K, 2K, 1080p, 720p) โดยไม่ทำให้กราฟิกบิดเบี้ยว
* **`window/size/resizable = true`:** อนุญาตให้ผู้เล่นย่อ-ขยายหน้าต่างเกมได้อย่างอิสระบนเดสก์ท็อป

### 3.2 ตัวจัดการหน้าต่างส่วนกลาง (`common/game_window.gd`)
ได้รับการปรับปรุงให้รองรับการเปิดใช้งานบนหน้าจอคอมพิวเตอร์หลากหลายขนาดอย่างชาญฉลาด:

1. **การจำกัดขนาดหน้าต่างขั้นต่ำ (`min_size`):**
   - ตั้งค่า `window.min_size = Vector2i(960, 540)`
   - ป้องกันไม่ให้ผู้เล่นย่อหน้าต่างจนเล็กเกินไปจนองค์ประกอบ UI หรือกล่องข้อความทับซ้อนกัน

2. **ระบบ Auto-fit สำหรับหน้าจอแล็ปท็อปขนาดเล็ก:**
   - เมื่อเปิดเกมในโหมด Windowed บนหน้าจอคอมพิวเตอร์ที่มีความละเอียดต่ำกว่า 1080p (เช่น 1366x768, 1440x900 หรือ 1600x900)
   - ฟังก์ชัน `_fit_windowed_to_screen()` จะคำนวณขนาดที่เหมาะสมโดยใช้พื้นที่ 85% ของหน้าจอที่ใช้งานได้ (`usable_rect`) และจัดกึ่งกลางหน้าจอให้อัตโนมัติ เพื่อไม่ให้หน้าต่างเกมล้นขอบจอ

3. **ปุ่มลัดสลับโหมดเต็มหน้าจอ (Fullscreen Shortcuts):**
   - รองรับ **`F11`** (มาตรฐานเกม PC)
   - รองรับ **`Alt + Enter`** (มาตรฐานสากลบน Windows)

4. **การปรับขนาด TopBar ใน Sandbox:**
   - ปรับปรุง `sandbox_game_view.tscn` ให้ `offset_bottom = 72.0` สอดคล้องกับมาตรฐานความสูง Navbar 72px ทั่วทั้งเกม

## 4. การแก้ไขปัญหาการ์ดด่านซ้อนทับกันในหน้าแผนที่หอคอย (Map Stage Cards Overlapping Bugfix)

### 4.1 ปัญหาที่พบ (Problem)
ในหน้าแผนที่หอคอยเลือกด่าน (`level_select_view.tscn`):
1. **ใน ACT 3 (ด่าน 21–40):** แท่นศิลาการ์ดด่านในแต่ละแถวชนและเกยซ้อนทับกันในแนวนอนอย่างรุนแรงถึง **100 px** ตลอดทั้ง 4 แถว (พบการซ้อนทับรวม 16 จุด)
2. **ใน ACT 2 (ด่าน 16–20):** การ์ดด่าน 18 และด่าน 19 ในส่วนล่างของลูปห้องทีมชนและเกยกันในแนวนอน **20 px**

### 4.2 สาเหตุเชิงลึก (Root Cause)
1. ในคอมมิตก่อนหน้า มีการกำหนดขนาดความกว้างของการ์ดแท่นศิลาด้วยสูตร:
   ```gdscript
   var p_width: float = maxf(float(stg["width"]) * 1.35, 340.0)
   ```
2. การบังคับ `maxf(..., 340.0)` ทำให้ **ทุกด่านในเกมมีความกว้างอย่างน้อย 340 px เสมอ**
3. แต่การจัดวางโครงสร้างแผนที่ในแต่ละ Act มีความหนาแน่นต่างกัน:
   * **ACT 3 (ยอดหอคอย):** ออกแบบเป็น Discrete Engineering Deck แบบ 5 คอลัมน์ (`x = 480, 720, 960, 1200, 1440`) ซึ่งระยะห่างระหว่างจุดกึ่งกลางคอลัมน์มีเพียง **240 px** เมื่อการ์ดกว้าง 340 px ทำให้ด้านซ้ายและขวาของการ์ดยื่นออกไปข้างละ 170 px (`170 + 170 = 340 px` เกินกว่าระยะห่าง 240 px) จึงเกิดการซ้อนทับกัน `340 - 240 = 100 px` ทุกคู่ในแถวเดียวกัน
   * **ACT 2 (ลูปห้องทีม):** ด่าน 18 (`x = 1120`) และด่าน 19 (`x = 800`) อยู่ที่ความสูงเดียวกัน (`y = 920`) ระยะห่างระหว่างกึ่งกลางคือ **320 px** เมื่อการ์ดกว้าง 340 px จึงซ้อนกัน `340 - 320 = 20 px`

### 4.3 วิธีการแก้ไข (Solution)
ปรับระบบคำนวณขนาดและ Typography ของการ์ดแท่นศิลาให้สอดคล้องกับลักษณะเฉพาะของแต่ละ Act (`level_select_view.gd`):

| Act | โครงสร้างแผนที่ | ความกว้างการ์ด (`p_width`) | ความสูงการ์ด (`plat_height`) | ระยะห่างแนวนอนระหว่างการ์ด | ผลการตรวจสอบ Overlap |
|---|---|:---:|:---:|:---:|:---:|
| **ACT 1 (ด่าน 01–15)** | บันไดวนเดี่ยว สลับซ้าย-กลาง-ขวา | `340 – 432 px` (`maxf(w * 1.35, 340)`) | 80 px | ปลอดภัย (ห่างแนวตั้ง ~145 px) | **0 จุด** (ผ่าน) |
| **ACT 2 (ด่าน 16–20)** | วงแหวน 5 ด่านรอบคลังเวท | **260 px** | 80 px | ช่องว่างระหว่างด่าน 18–19 = **60 px** | **0 จุด** (ผ่าน) |
| **ACT 3 (ด่าน 21–40)** | กริดวิศวกรรม 5 คอลัมน์ x 4 แถว | **204 px** | 70 px | ช่องว่างแนวนอน = **36 px**<br>ช่องว่างแนวตั้ง = **20 px** | **0 จุด** (ผ่าน) |

นอกจากนี้ ยังปรับขนาดของเหรียญเลขด่าน (`num_badge`), ฟอนต์ชื่อด่าน/คำสั่ง Git, และ Margin ภายในการ์ดของ ACT 3 ให้กะทัดรัดพอดี (`num_badge = 42x42`, ฟอนต์ 15/12px) ป้องกันข้อความล้น และขยาย `TowerContent` ใน `level_select_view.tscn` เป็น `1760 px` ให้เต็มพื้นที่โถงหอคอยอย่างสมบูรณ์

## 5. การปรับตำแหน่งและข้อความแนะนำการเลื่อนแผนที่ (Map Navigation Hint Adjustment)

### 5.1 ปัญหาที่พบ (Problem)
กล่องข้อความแนะนำการเลื่อนหอคอย (`MapNavHint`) ที่มุมล่างขวาของหน้าจอมีขอบขวายื่นออกไปที่ `offset_right = -24.0` ส่งผลให้ข้อความยาวล้นไปทับซ้อนกับแถบ Scrollbar และเสาอิฐด้านขวา (`RightPillar`) อีกทั้งข้อความเรียงเป็นบรรทัดเดียวยาวจนบดบังทัศนียภาพ

### 5.2 วิธีการแก้ไข (Solution)
ปรับแต่งโครงสร้างและการจัดวางใน `level_select_view.tscn`:
1. **ขยับตำแหน่งเข้ามาด้านใน:** เปลี่ยนพิกัดขอบขวาจาก `offset_right = -24.0` เป็น `-120.0` (เว้นระยะปลอดภัยจากเสาอิฐ 40px และจาก Scrollbar 26px ไม่บังเสาอิฐอีกต่อไป) และตั้งขอบซ้ายที่ `offset_left = -360.0` (ความกว้างรวม 240px)
2. **ปรับความสูงและระยะแนวตั้ง:** ปรับ `offset_top = -158.0`, `offset_bottom = -110.0` (ความสูง 48px ลอยเหนือ BottomHUD อย่างพอดี)
3. **จัดย่อหน้า 2 บรรทัดและจัดกึ่งกลาง:**
   - บรรทัดที่ 1: `ใช้ W / S หรือเลื่อนลูกกลิ้ง`
   - บรรทัดที่ 2: `เพื่อสำรวจหอคอย`
   - จัดกึ่งกลางทั้งแนวนอนและแนวตั้ง (`horizontal_alignment = 1`, `vertical_alignment = 1`)
