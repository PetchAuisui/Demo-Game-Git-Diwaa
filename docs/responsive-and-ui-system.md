# มาตรฐาน Responsive, ระบบ Navbar และการจัดการหน้าต่าง (Responsive & UI System Guide)

เอกสารนี้รวบรวมรายละเอียดการปรับแต่งระบบ Responsive, การควบคุมหน้าต่างเกมบนเครื่องคอมพิวเตอร์, การแก้ไขสัดส่วนและระยะห่างของแถบนำทาง (Navbar), และการทำงานของระบบสุ่มสีหมวกประจำเซสชันในเกม **GIT DI WAA**

---

## 1. การแก้ไขบั๊กระยะห่าง Navbar (Brand Button Spacing Bugfix)

### 1.1 ปัญหาที่พบ (Problem)
ในแถบนำทางด้านบน (Navbar) เกิดช่องว่างขนาดใหญ่ที่ผิดปกติระหว่างข้อความชื่อเกม **`GIT DI WAA`** กับเส้นขีดคั่นแนวตั้ง **`|`** ทำให้ดูแหว่งและไม่สมดุล เมื่อเทียบกับระยะห่างระหว่างเส้นขีดคั่นกับป้ายชื่อหน้า (เช่น `TOWER ROADMAP`, `SANDBOX`, `MAIN CONSOLE`, `DRESSING ROOM`)

```text
[ก่อนแก้ไข - ระยะห่างผิดปกติ]
[หมวก] GIT DI WAA                |   TOWER ROADMAP
      |<------- 53 px --------->|<- 16 px ->|

[หลังแก้ไข - สมมาตรสวยงาม]
[หมวก] GIT DI WAA    |   TOWER ROADMAP
      |<-- 17 px -->|<- 16 px ->|
```

### 1.2 สาเหตุเชิงลึก (Root Cause)
1. ตัวอักษร `GIT DI WAA` ใช้ฟอนต์ `Bungee-Regular.ttf` ขนาด 26px วัดความกว้างจริงของตัวอักษรได้ **157 px**
2. ข้อความถูกวางเยื้องจากขอบซ้ายของปุ่มแบรนด์ (`BrandBtn`) ด้วย `offset_left = 16.0` ทำให้ข้อความสิ้นสุดที่พิกัด `x = 173 px`
3. เดิม `BrandBtn` ถูกตั้งค่าความกว้างขั้นต่ำไว้เกินจริงที่ `custom_minimum_size = Vector2(210, 48)` ทำให้เกิดพื้นที่ว่างเปล่าที่มองไม่เห็นภายในปุ่มด้านขวาถึง **37 px** (`210 - 173 = 37`)
4. เมื่อรวมกับระยะห่างระหว่าง Element (`separation = 16 px`) ของ `HBoxContainer` ทำให้ระยะห่างจริงจากตัวหนังสือถึงเส้นขีดคั่นกลายเป็น **53 px** (`37 + 16`) ในขณะที่ฝั่งขวาของเส้นคั่นห่างเพียง **16 px**

### 1.3 วิธีการแก้ไข (Solution)
ปรับขนาดของ `BrandBtn` และขอบเขตของ Label ให้พอดีกับตัวอักษรที่เรนเดอร์จริงคือ **174 px** ในทุก Scene ที่มี Navbar:

| ไฟล์ Scene | โหนดที่แก้ไข | ค่าเดิม | ค่าที่แก้ไขใหม่ |
|---|---|---|---|
| `features/level_select/level_select_view.tscn` | `BrandBtn`<br>`BrandTitle` | `custom_minimum_size = Vector2(210, 48)`<br>`offset_right = 205.0` | `custom_minimum_size = Vector2(174, 48)`<br>`offset_right = 174.0` |
| `features/sandbox/top_bar_panel.tscn` | `BrandBtn`<br>`BrandLabel` | `custom_minimum_size = Vector2(210, 48)`<br>`offset_right = 205.0` | `custom_minimum_size = Vector2(174, 48)`<br>`offset_right = 174.0` |
| `features/start/start_top_bar.tscn` | `BrandBtn`<br>`BrandTitle` | `custom_minimum_size = Vector2(210, 48)`<br>`offset_right = 205.0` | `custom_minimum_size = Vector2(174, 48)`<br>`offset_right = 174.0` |
| `features/start/dressing_room_view.tscn` | `BrandBtn`<br>`BrandTitle` | `custom_minimum_size = Vector2(210, 48)`<br>`offset_right = 205.0` | `custom_minimum_size = Vector2(174, 48)`<br>`offset_right = 174.0` |

## 2. ระบบสุ่มสีหมวกแม่มดประจำเซสชัน (Session Hat Color Randomization)

### 2.1 ปัญหาที่พบ (Problem)
หมวกแม่มดบนตัวอักษร 'G' ใน Navbar เปลี่ยนสีสุ่มไปเรื่อย ๆ ทุกครั้งที่ผู้เล่นสลับหน้าจอ (เช่น จากหน้าแรก ➔ เลือกด่าน ➔ ย้อนกลับหน้าแรก หมวกเปลี่ยนสีตลอดเวลา)

### 2.2 สาเหตุเชิงลึก (Root Cause)
1. **ลำดับการประมวลผลของ Godot (Node Lifecycle):** โหนดลูกจะเข้าสู่สถานะ `_ready()` ก่อนโหนดแม่ ในหน้าจอหลัก `start_view.tscn`:
   - โหนดลูก `TopBar` จะรัน `_ready()` ก่อน และเรียก `GameProgressManager.get_current_hat_texture()` ซึ่งทำการสุ่มสีแรก (เช่น สีม่วง) และนำมาแสดงผล
   - จากนั้นโหนดแม่ `StartViewController` รัน `_ready()` ซึ่งมีโค้ด `GameProgressManager.randomize_hat_color()` สั่งสุ่มสีทับทันที (เช่น เปลี่ยนเป็นสีเขียว)
   - ผลลัพธ์: หน้าจอแรกแสดงสีม่วง แต่หน่วยความจำระบบกลายเป็นสีเขียว พอคลิกไปหน้าเลือกด่าน หน้าเลือกด่านจึงแสดงสีเขียว ทำให้ดูเหมือนหมวกเปลี่ยนสีตอนสลับหน้า
2. **การสุ่มซ้ำเมื่อย้อนกลับ:** เมื่อใดก็ตามที่กดย้อนกลับมายัง `start_view.tscn` โค้ดใน `_ready()` ของหน้าเริ่มเกมจะรันใหม่และสุ่มสีใหม่อีกครั้งเสมอ

### 2.3 วิธีการแก้ไข (Solution)
1. นำคำสั่ง `GameProgressManager.randomize_hat_color()` ออกจาก `_ready()` ของ `features/start/start_view_controller.gd`
2. ให้ `GameProgressManager` รับผิดชอบการสุ่มแบบ **Lazy Initialization** กล่าวคือ เมื่อเริ่มเปิดเกม ค่า `_current_hat_color` จะเริ่มต้นที่ `-1` และจะทำการสุ่มสีเพียง **ครั้งเดียวเท่านั้น** เมื่อมีการเรียกใช้งานครั้งแรก:

```gdscript
# common/game_progress_manager.gd
static var _current_hat_color: int = -1

static func randomize_hat_color() -> int:
	_current_hat_color = randi() % 3
	return _current_hat_color

static func get_current_hat_color() -> int:
	if _current_hat_color < 0:
		randomize_hat_color()
	return _current_hat_color
```

ผลลัพธ์: หมวกจะสุ่ม 1 ครั้งเมื่อเปิดเกม และคงสีเดิมไว้ตลอดทั้งเซสชัน ไม่ว่าจะสลับไปหน้าเลือกด่าน, ห้องแต่งตัว, หน้าทดลองเล่น หรือย้อนกลับมาหน้าหลัก

## 3. ระบบ Responsive และการแสดงผลหน้าต่างคอมพิวเตอร์ (Desktop Responsive System)

### 3.1 การตั้งค่าหน้าจอหลัก (Project Display Settings)
อ้างอิงจาก `game/project.godot`:

```ini
[display]
window/size/viewport_width=1920
window/size/viewport_height=1080
window/size/mode=3
window/size/window_width_override=1920
window/size/window_height_override=1080
window/size/resizable=true
window/stretch/mode="canvas_items"
window/stretch/aspect="keep"
window/stretch/scale_mode="fractional"
```

* **`stretch/mode = "canvas_items"`:** องค์ประกอบภาพ 2D และ UI ทั้งหมดจะคงความคมชัดตามพิกเซล และข้อความจะถูกเรนเดอร์แบบ Sub-pixel คมชัดทุกขนาดหน้าจอ
* **`stretch/aspect = "keep"`:** รักษาสัดส่วน 16:9 สเกลเต็มจออัตโนมัติบนจอทุกความละเอียด (เช่น 4K, 2K, 1080p, 720p) โดยไม่ทำให้กราฟิกบิดเบี้ยว
* **`window/size/resizable = true`:** อนุญาตให้ผู้เล่นย่อ-ขยายหน้าต่างเกมได้อย่างอิสระบนเดสก์ท็อป

### 3.2 ตัวจัดการหน้าต่างส่วนกลาง (`common/game_window.gd`)
ได้รับการปรับปรุงให้รองรับการเปิดใช้งานบนหน้าจอคอมพิวเตอร์หลากหลายขนาดอย่างชาญฉลาด:

1. **การจำกัดขนาดหน้าต่างขั้นต่ำ (`min_size`):**
   - ตั้งค่า `window.min_size = Vector2i(960, 540)`
   - ป้องกันไม่ให้ผู้เล่นย่อหน้าต่างจนเล็กเกินไปจนองค์ประกอบ UI หรือกล่องข้อความทับซ้อนกัน

2. **ระบบ Auto-fit สำหรับหน้าจอแล็ปท็อปขนาดเล็ก:**
   - เมื่อเปิดเกมในโหมด Windowed บนหน้าจอคอมพิวเตอร์ที่มีความละเอียดต่ำกว่า 1080p (เช่น 1366x768, 1440x900 หรือ 1600x900)
   - ฟังก์ชัน `_fit_windowed_to_screen()` จะคำนวณขนาดที่เหมาะสมโดยใช้พื้นที่ 85% ของหน้าจอที่ใช้งานได้ (`usable_rect`) และจัดกึ่งกลางหน้าจอให้อัตโนมัติ เพื่อไม่ให้หน้าต่างเกมล้นขอบจอ

3. **ปุ่มลัดสลับโหมดเต็มหน้าจอ (Fullscreen Shortcuts):**
   - รองรับ **`F11`** (มาตรฐานเกม PC)
   - รองรับ **`Alt + Enter`** (มาตรฐานสากลบน Windows)

4. **การปรับขนาด TopBar ใน Sandbox:**
   - ปรับปรุง `sandbox_game_view.tscn` ให้ `offset_bottom = 72.0` สอดคล้องกับมาตรฐานความสูง Navbar 72px ทั่วทั้งเกม

## 4. การแก้ไขปัญหาการ์ดด่านซ้อนทับกันในหน้าแผนที่หอคอย (Map Stage Cards Overlapping Bugfix)

### 4.1 ปัญหาที่พบ (Problem)
ในหน้าแผนที่หอคอยเลือกด่าน (`level_select_view.tscn`):
1. **ใน ACT 3 (ด่าน 21–40):** แท่นศิลาการ์ดด่านในแต่ละแถวชนและเกยซ้อนทับกันในแนวนอนอย่างรุนแรงถึง **100 px** ตลอดทั้ง 4 แถว (พบการซ้อนทับรวม 16 จุด)
2. **ใน ACT 2 (ด่าน 16–20):** การ์ดด่าน 18 และด่าน 19 ในส่วนล่างของลูปห้องทีมชนและเกยกันในแนวนอน **20 px**

### 4.2 สาเหตุเชิงลึก (Root Cause)
1. ในคอมมิตก่อนหน้า มีการกำหนดขนาดความกว้างของการ์ดแท่นศิลาด้วยสูตร:
   ```gdscript
   var p_width: float = maxf(float(stg["width"]) * 1.35, 340.0)
   ```
2. การบังคับ `maxf(..., 340.0)` ทำให้ **ทุกด่านในเกมมีความกว้างอย่างน้อย 340 px เสมอ**
3. แต่การจัดวางโครงสร้างแผนที่ในแต่ละ Act มีความหนาแน่นต่างกัน:
   * **ACT 3 (ยอดหอคอย):** ออกแบบเป็น Discrete Engineering Deck แบบ 5 คอลัมน์ (`x = 480, 720, 960, 1200, 1440`) ซึ่งระยะห่างระหว่างจุดกึ่งกลางคอลัมน์มีเพียง **240 px** เมื่อการ์ดกว้าง 340 px ทำให้ด้านซ้ายและขวาของการ์ดยื่นออกไปข้างละ 170 px (`170 + 170 = 340 px` เกินกว่าระยะห่าง 240 px) จึงเกิดการซ้อนทับกัน `340 - 240 = 100 px` ทุกคู่ในแถวเดียวกัน
   * **ACT 2 (ลูปห้องทีม):** ด่าน 18 (`x = 1120`) และด่าน 19 (`x = 800`) อยู่ที่ความสูงเดียวกัน (`y = 920`) ระยะห่างระหว่างกึ่งกลางคือ **320 px** เมื่อการ์ดกว้าง 340 px จึงซ้อนกัน `340 - 320 = 20 px`

### 4.3 วิธีการแก้ไข (Solution)
ปรับระบบคำนวณขนาดและ Typography ของการ์ดแท่นศิลาให้สอดคล้องกับลักษณะเฉพาะของแต่ละ Act (`level_select_view.gd`):

| Act | โครงสร้างแผนที่ | ความกว้างการ์ด (`p_width`) | ความสูงการ์ด (`plat_height`) | ระยะห่างแนวนอนระหว่างการ์ด | ผลการตรวจสอบ Overlap |
|---|---|:---:|:---:|:---:|:---:|
| **ACT 1 (ด่าน 01–15)** | บันไดวนเดี่ยว สลับซ้าย-กลาง-ขวา | `340 – 432 px` (`maxf(w * 1.35, 340)`) | 80 px | ปลอดภัย (ห่างแนวตั้ง ~145 px) | **0 จุด** (ผ่าน) |
| **ACT 2 (ด่าน 16–20)** | วงแหวน 5 ด่านรอบคลังเวท | **260 px** | 80 px | ช่องว่างระหว่างด่าน 18–19 = **60 px** | **0 จุด** (ผ่าน) |
| **ACT 3 (ด่าน 21–40)** | กริดวิศวกรรม 5 คอลัมน์ x 4 แถว | **204 px** | 70 px | ช่องว่างแนวนอน = **36 px**<br>ช่องว่างแนวตั้ง = **20 px** | **0 จุด** (ผ่าน) |

นอกจากนี้ ยังปรับขนาดของเหรียญเลขด่าน (`num_badge`), ฟอนต์ชื่อด่าน/คำสั่ง Git, และ Margin ภายในการ์ดของ ACT 3 ให้กะทัดรัดพอดี (`num_badge = 42x42`, ฟอนต์ 15/12px) ป้องกันข้อความล้น และขยาย `TowerContent` ใน `level_select_view.tscn` เป็น `1760 px` ให้เต็มพื้นที่โถงหอคอยอย่างสมบูรณ์

## 5. การปรับตำแหน่งและข้อความแนะนำการเลื่อนแผนที่ (Map Navigation Hint Adjustment)

### 5.1 ปัญหาที่พบ (Problem)
กล่องข้อความแนะนำการเลื่อนหอคอย (`MapNavHint`) ที่มุมล่างขวาของหน้าจอมีขอบขวายื่นออกไปที่ `offset_right = -24.0` ส่งผลให้ข้อความยาวล้นไปทับซ้อนกับแถบ Scrollbar และเสาอิฐด้านขวา (`RightPillar`) อีกทั้งข้อความเรียงเป็นบรรทัดเดียวยาวจนบดบังทัศนียภาพ

### 5.2 วิธีการแก้ไข (Solution)
ปรับแต่งโครงสร้างและการจัดวางใน `level_select_view.tscn`:
1. **ขยับตำแหน่งเข้ามาด้านใน:** เปลี่ยนพิกัดขอบขวาจาก `offset_right = -24.0` เป็น `-120.0` (เว้นระยะปลอดภัยจากเสาอิฐ 40px และจาก Scrollbar 26px ไม่บังเสาอิฐอีกต่อไป) และตั้งขอบซ้ายที่ `offset_left = -360.0` (ความกว้างรวม 240px)
2. **ปรับความสูงและระยะแนวตั้ง:** ปรับ `offset_top = -158.0`, `offset_bottom = -110.0` (ความสูง 48px ลอยเหนือ BottomHUD อย่างพอดี)
3. **จัดย่อหน้า 2 บรรทัดและจัดกึ่งกลาง:**
   - บรรทัดที่ 1: `ใช้ WASD หรือลูกศร`
   - บรรทัดที่ 2: `เพื่อสำรวจหอคอย`
   - จัดกึ่งกลางทั้งแนวนอนและแนวตั้ง (`horizontal_alignment = 1`, `vertical_alignment = 1`)

## 6. ระบบแสดงผลสถานะด่าน (Level State Colors & Readability)

ระบบปรับแต่งโทนสีแท่นศิลาของด่านตามสไตล์โกธิคแฟนตาซี 4 สถานะ:

| สถานะด่าน | สีพื้นหลังหินศิลา | สีกรอบแท่นหิน | สัญลักษณ์/เงา | สีข้อความชื่อด่าน |
|---|---|---|---|---|
| **Current Level** (ด่านปัจจุบัน) | สีน้ำตาลอุ่น `(0.18, 0.13, 0.08)` | ขอบทองอำพันเรืองแสง `(0.96, 0.62, 0.07)` | แสงออร่าสีทอง Shadow 8px | สีทองอำพันสว่าง `(0.98, 0.88, 0.47)` |
| **Completed Levels** (ด่านที่ผ่านแล้ว) | สีศิลาเขียวมอสโกธิค `(0.08, 0.15, 0.11)` | สีเขียวหยกหม่น `(0.24, 0.50, 0.34)` | ดาวทอง ★★★ ชัดเจน | สีเขียวมิ้นต์สว่าง `(0.84, 0.94, 0.88)` |
| **Available Levels** (ด่านที่ปลดล็อก) | สีหินชนวนฟ้า-เทา `(0.11, 0.14, 0.19)` | ขอบเหล็กกล้าสีฟ้า-เทา `(0.36, 0.48, 0.64)` | เงาลึก Shadow 3px | สีขาวน้ำแข็ง `(0.88, 0.93, 0.98)` |
| **Locked Levels** (ด่านที่ล็อก) | สีฟ้า-เทาหม่นมืด `(0.09, 0.11, 0.15)` | ขอบหินโกธิค `(0.22, 0.27, 0.36)` | แม่กุญแจเหล็กเงินเงางามชัดเจน | สีเงินหินชนวนอ่านง่าย `(0.68, 0.75, 0.84)` |

* **ปรับปรุงความสว่าง:** เพิ่มความสว่างของแท่นศิลาด่านที่ล็อกขึ้นจากสีดำทึบเดิม (`0.06` ➔ `0.09`) พร้อมขอบหินและชื่อด่านที่อ่านออกได้อย่างชัดเจนแต่ยังคงความรู้สึกลึกลับ
* **แม่กุญแจสีเงินเมทัลลิก:** ปรับ Modulate ของกุญแจล็อกเป็นสีเงินเมทัลลิกมองเห็นได้เด่นชัด

## 7. ระบบเส้นทางแผนที่เชื่อมต่อครบ 40 ด่าน (Roadmap Path System)

1. **เชื่อมต่อครบทุกด่าน:** เพิ่มการเชื่อมโยงเส้นประโค้งมน (Bézier Curves) ของ ACT 3 (ด่าน 21–40) ครบทุกแถว พร้อมเส้นเลี้ยวเชื่อมระหว่างแถวอย่างลื่นไหล
2. **การแยกสถานะของเส้นทาง (Path States):**
   - **Completed Path:** เส้นทางสีเขียวมรกตหม่น `(0.35, 0.78, 0.50)` พร้อมแสงเรืองรอง (Animated Pulse Glow) หายใจเป็นจังหวะนุ่มนวล
   - **Current Path:** เส้นทางสีส้มทองอบอุ่น `(0.96, 0.65, 0.15)` เชื่อมต่อจากเส้นทางเดิมตรงสู่ด่านปัจจุบันของตัวละคร
   - **Locked Path:** เส้นทางสีฟ้า-เทาหม่น `(0.24, 0.30, 0.40)` มองเห็นแนวทางได้ชัดเจนโดยไม่แย่งความสนใจ
3. **Layering:** เส้นทางเรนเดอร์อยู่บน `PathRenderer` ซึ่งอยู่ด้านหลังแท่นศิลาด่านและตัวละครเสมอ

## 8. ระบบควบคุมตัวละคร 4 ทิศทาง (WASD & Arrow Keys Navigation)

รองรับการเคลื่อนที่อย่างสมบูรณ์แบบทั้ง 4 ทิศทาง (`W/A/S/D` และปุ่มลูกศร `Up/Down/Left/Right`):
- **ACT 1 (บันไดวนไต่ขึ้น):** W/Up และ S/Down ไต่ขึ้น-ลงตามบันไดหิน, A/Left และ D/Right ขยับไปตามตำแหน่งด่านซ้าย-ขวา
- **ACT 2 (วงแหวนลูปห้องทีม):** นำทางตามวงกลม GitHub Flow ครบทั้ง 4 ทิศทาง
- **ACT 3 (กริดวิศวกรรม 5x4):**
  - **A / D (Left / Right):** เลื่อนไปมาระหว่างคอลัมน์ในแถวเดียวกัน
  - **W / S (Up / Down):** เลื่อนขึ้น-ลงระหว่างแถวในคอลัมน์เดิมอย่างแม่นยำ
- **ขอบเขตปลอดภัย:** ตัวละครถูกจำกัดให้อยู่ในขอบเขตด่าน 1–40 เสมอ และหากผู้เล่นกดไปยังด่านที่ล็อก ระบบจะส่งเสียงเตือนและแสดงข้อความล็อกโดยไม่ให้ตัวละครกระโดดข้าม

## 9. แถบนำทาง Act Navigation และปุ่มดำเนินต่อ (Act Progress & Header Controls)

1. **ชิปแสดงความคืบหน้าของบท (Act Progress Chip):**
   - แสดงผลความคืบหน้าแบบ Real-time เช่น `ACT 1 — 3 / 15 LEVELS`, `ACT 2 — 0 / 5 LEVELS`, `ACT 3 — 0 / 20 LEVELS`
   - เปลี่ยนโทนสีตามสถานะ: สีทอง (กำลังเล่น), สีเขียวมรกต (เคลียร์ครบแล้ว), สีเทาหม่น (ยังไม่ปลดล็อก)
2. **สถานะปุ่ม Act:**
   - **Current Act:** ไฮไลต์ขอบล่างสีทองอำพัน
   - **Completed Act:** แสดงเครื่องหมาย `✓` พร้อมสไตล์สีเขียวโกธิค
   - **Locked Act:** แสดงไอคอน `🔒` สีเทาหม่น และแจ้งเตือนเมื่อคลิก
3. **ปุ่ม "ดำเนินต่อ ➔" (Continue Button):**
   - ปรับปรุงจากปุ่มเดิมให้กลายเป็นปุ่ม Continue สไตล์ RPG เด่นชัด
   - กดแล้วจะเลื่อนกล้องและพาตัวละครไปยังด่านล่าสุดที่ปลดล็อกทันทีโดยไม่รีเซ็ตความคืบหน้าเดิมของผู้เล่น

## 10. การปรับปรุงความแม่นยำในการควบคุมและความนุ่มนวลของกล้อง (Discrete Navigation & Smooth Pacing)

1. **การควบคุมแบบ 1 ด่านต่อ 1 การกด (Strict 1-Step Discrete Movement):**
   - **สาเหตุของบั๊กกระโดด 3 ด่านเดิม:** ในฟังก์ชัน `_navigate_directional` เดิม เมื่ออยู่ใน Act 3 หรือ Act 2 มีการคำนวณเป้าหมายข้ามแถวกริด (เช่น `target_idx = base_idx - 5` หรือตกมาที่ด่าน 20) ทำให้คิวเดินอัตโนมัติสั่งให้ตัวละครกระโดดต่อเนื่อง 3–5 ด่านรวดในการกดเพียงครั้งเดียว
   - **การแก้ไข:** ปรับปรุงให้อินพุตลูกศร (และ WASD) ก้าวไปยังด่านติดกันตามเส้นทางไต่หอคอยทีละ 1 ด่านอย่างเคร่งครัด:
     - `Arrow Down / S`: ถอยลงหอคอยไปด่านก่อนหน้า (`base_idx - 1`) ทีละ 1 ด่านเสมอ ไม่มีการข้ามด่าน
     - `Arrow Up / W`: ก้าวขึ้นหอคอยไปด่านถัดไป (`base_idx + 1`) ทีละ 1 ด่านเสมอ
     - `Arrow Left / Right (A / D)`: นำทางไปยังด่านติดกันตามทิศทางแท่นหินซ้าย-ขวาอย่างแม่นยำ
   - **Jump Guard:** บล็อกการรับอินพุตทิศทางขณะที่ตัวละครกำลังลอยตัวอยู่กลางอากาศ (`if _is_jumping: return`) ป้องกันการสะสมคิวกดรัวจากการเคาะปุ่มหรือ Key Repeat

2. **ปรับความเร็วและจังหวะการเคลื่อนที่ (Smooth Jump & Camera Tracking):**
   - **ความเร็วกระโดด:** ปรับระยะเวลาของ `_jump_tween` จากเดิม `0.32s - 0.42s` เป็น `0.50s` (และ `0.72s` สำหรับการข้ามชั้น Act 1 ไป Act 2) โดยใช้ `Tween.TRANS_SINE` ร่วมกับ `Tween.EASE_IN_OUT` ทำให้พาราโบลาการลอยตัวนุ่มนวลเป็นธรรมชาติ ไม่พุ่งเร็วจนเกินไป
   - **การเลื่อนกล้องตามตัวละคร:** ปรับระยะเวลาของ `_scroll_to_y` จากเดิม `0.22s` (ซึ่งเร็วเกินไปจนภาพสะบัด) เป็น `0.48s` ด้วย `Tween.TRANS_CUBIC` และ `Tween.EASE_OUT` ทำให้มุมมองกล้องเลื่อนติดตามตัวละครอย่างนุ่มนวลทั้งตอนก้าวไปข้างหน้าและตอนถอยหลัง
   - **จังหวะลงพื้น (Landing Rhythm):** เพิ่มช่วงหยุดพักเบา ๆ `0.06s` ระหว่างการกระโดดต่อเนื่อง ทำให้รู้สึกถึงน้ำหนักของการลงสู่แท่นหินแต่ละด่าน

3. **กล่องข้อความแนะนำ (MapNavHint):**
   - จัดวางข้อความ 2 บรรทัดกึ่งกลาง:
     ```
     ใช้ W / S หรือเลื่อนลูกกลิ้ง
     เพื่อสำรวจหอคอย
     ```
   - ระยะห่างเว้นจากขอบขวา (`offset_right = -120.0`) ไม่ทับเสาอิฐโกธิคและ Scrollbar ในทุกระดับความละเอียดหน้าจอ

## 11. การแก้ไขตำแหน่งหมวกแม่มดบนปุ่ม Brand (BrandHat Resting State Fix)

- **สาเหตุของอาการหมวกลอยค้าง:**
  - ในไฟล์ Scene ทั้ง 4 หน้าจอ (`start_top_bar.tscn`, `level_select_view.tscn`, `top_bar_panel.tscn`, `dressing_room_view.tscn`) มีการตั้งค่าเริ่มต้นของ `BrandHat` ไว้ที่ `offset_top = -7.0` (ซึ่งเป็นพิกัด Y ของแอนิเมชันกระโดดลอยตอน Hover)
  - เมื่อเปิดเข้าสู่เกมหรือเปลี่ยนหน้าจอใหม่ หมวกจึงเกิดมาในสถานะลอยตัวค้างไว้ในอากาศ (`position.y = -7.0`) จนกว่าผู้เล่นจะเลื่อนเมาส์ไปชี้แล้วเลื่อนออก หมวกจึงจะยอมตกลงมาที่พิกัดสวมปกติ (`position.y = -4.0`)
- **การแก้ไข:**
  - ปรับตำแหน่งเริ่มต้นในไฟล์ Scene ทั้ง 4 ฉากให้เป็นพิกัดสวมทับตัวอักษรอย่างถูกต้อง:
    - `offset_top = -4.0`
    - `offset_bottom = 22.0` (ความสูงคงที่ 26px)
  - ในฟังก์ชัน `_ready()` ของ Script ทุกหน้าจอ เพิ่มการรีเซ็ตพิกัดและมุมเอียงเริ่มต้นอย่างชัดเจน:
    ```gdscript
    brand_hat.position.y = -4.0
    brand_hat.rotation_degrees = 0.0
    ```
  - ทำให้เมื่อเปิดเข้าเกมหรือสลับหน้าจอ หมวกจะสวมประดับอยู่บนตัวอักษร 'G' ของโลโก้อย่างสวยงามเป็นธรรมชาติ ไม่ลอยค้างอีกต่อไป และยังคงแอนิเมชันกระดุกกระดิกเมื่อนำเมาส์ไป Hover ได้อย่างสมบูรณ์

## 12. การปรับปรุง Navbar ให้เป็นแบบมินิมอลโกธิคแบบรวมเป็นหนึ่งเดียว (Unified Minimal Gothic Navbar & Flat Tabs)

### 12.1 การยกเลิกดีไซน์กล่องซ้อนกล่อง (Elimination of Box-in-Box Containers)
เดิมทีแถบนำทางด้านบน (Header Navigation) ของหน้าเลือกด่านประกอบไปด้วยชิ้นส่วนที่เป็นกล่องสี่เหลี่ยมมีขอบหนาและพื้นหลังทึบซ้อนกันหลายชั้น (ปุ่มเลือก Act แต่ละอันมีขอบกล่อง, ชิปแสดงความคืบหน้ามีขอบกล่อง, และปุ่มดำเนินต่อก็มีขอบกล่องหนา) ทำให้ส่วนหัวดูหนาทึบและแย่งสายตาจากแผนที่หอคอย

**แนวทางการปรับปรุง:**
- ยกเลิกขอบสี่เหลี่ยมหนา (`StyleBoxFlat` ที่มีกรอบ 4 ด้าน) และพื้นหลังซ้อนหลายชั้นทั้งหมด
- ปรับพื้นหลังของ Navbar ให้ใช้สีพื้นหลังโกธิคหม่น `#100F1C` (`Color(0.063, 0.059, 0.11, 0.98)`) เพื่อให้แถบนำทางเป็นเนื้อเดียวกับบรรยากาศโดยรวม

### 12.2 การเปลี่ยนปุ่ม Act เป็น Flat Tabs
เปลี่ยนปุ่มเลือกบทเป็นแท็บข้อความแบนราบ (Flat Text Tabs) โดยไม่มีกรอบกล่องสี่เหลี่ยมล้อมรอบ:
- **Active Act (บทที่กำลังเลือกดู):**
  - ข้อความสีทองแอนทีค (Antique Gold `#B89A67`)
  - มีเส้นขีดใต้บาง ๆ 2px (`border_width_bottom = 2`) สีทองแอนทีคใต้แท็บ
  - ไม่มีกรอบกล่องสี่เหลี่ยมล้อมรอบ และไม่มีแสงฟุ้งเกินจำเป็น
- **Completed Act (บทที่เคลียร์ด่านครบแล้ว):**
  - ข้อความสีเขียวเสจหม่น (Muted Sage Green `#829A91`)
  - แสดงเครื่องหมายติ๊กถูก `✓` ต่อท้ายอย่างเรียบหรู (เช่น `ACT 1 ✓`)
- **Locked Act (บทที่ยังล็อกอยู่):**
  - ข้อความสีม่วงลาเวนเดอร์-เทาหม่น (Muted Lavender-Gray `#77758D`)
  - ปรับลดน้ำหนักสายตา และตัดไอคอนกุญแจ 🔒 เพื่อความคลีนและมินิมอล
- **Unlocked Inactive Act (บทที่ปลดล็อกแล้วแต่ไม่ได้เลือก):**
  - ข้อความสีเทารอง (Secondary `#9A96AA`) และจะไฮไลต์เป็นสีขาวสว่าง (`#E4DFD5`) เมื่อนำเมาส์ไปชี้ (Hover)

### 12.3 การลดรูปตัวบอกความคืบหน้า (Inline Progress Indicator)
- ปลดกรอบ Container ออกทั้งหมด และใช้สไตล์ `StyleBoxEmpty`
- แสดงความคืบหน้าเป็นข้อความแบบบรรทัดเดียว (Inline Text) เช่น:
  ```text
  ACT 1 · 0 / 15 LEVELS
  ACT 2 · 5 / 5 LEVELS
  ACT 3 · 12 / 20 LEVELS
  ```
- ใช้ตัวคั่นจุดกึ่งกลาง (Middle Dot `·`) และฟอนต์ขนาด 13px สี `#9A96AA` เพื่อให้ทำหน้าที่เป็นข้อมูลบริบทประกอบ ไม่แย่งความเด่นจากแท็บเลือกบท

### 12.4 ปุ่มดำเนินต่อสไตล์ Flat Text-Button
- ปรับเปลี่ยนจากปุ่มกล่องหนาเดิม ให้กลายเป็น Flat Text Button สไตล์มินิมอลโกธิค:
  ```text
  ดำเนินต่อ →
  ```
- ใช้ข้อความและลูกศรบาง `→` (Unicode `\u2192`) สีทองแอนทีค (`#B89A67`)
- สถานะ Hover จะสว่างขึ้นเป็นสีขาวงาช้าง (`#E4DFD5`) อย่างนุ่มนวลโดยไม่ใส่แสง Glow ฟุ้ง
- คงพฤติกรรมเดิม: เมื่อคลิกจะเลื่อนกล้องและพาตัวละครไปยังด่านล่าสุดที่ปลดล็อกหรือด่านปัจจุบันทันที

## 13. การปรับปรุงจังหวะการสลับการ์ด ความนุ่มนวลระหว่าง Act 1-2 และการล็อกขนาด Navbar ป้องกันการสั่นไหว

### 13.1 การสลับการ์ดและสถานะด่านเมื่อตัวละครลงสู่แท่นหิน (Landing-Triggered Card Update)
- **ปัญหาเดิม:** เมื่อผู้เล่นกดปุ่มทิศทางหรือคลิกเลือกด่าน ระบบเดิมสั่งเปลี่ยนไฮไลต์การ์ดด่านบนแผนที่ (`_update_platform_highlight`) และอัปเดตข้อมูลบนกล่อง HUD ด้านล่าง (`_update_hud_display`) ตั้งแต่วินาทีแรกของการกระโดด (`t = 0.0`) ส่งผลให้การ์ดเปลี่ยนไปแสดงด่านปลายทางทันที ทั้ง ๆ ที่ตัวละครเวลเพิ่งเริ่มออกตัวหรือยังลอยอยู่กลางอากาศ
- **การแก้ไข:**
  - คงสถานะไฮไลต์และการ์ด HUD ของด่านต้นทางไว้ตลอดช่วงเวลาที่ตัวละครกำลังเคลื่อนที่อยู่ในอากาศ
  - ปิดกั้นไม่ให้ฟังก์ชันเลื่อนมุมกล้อง (`_scroll_to_stage_idx`) อัปเดต HUD ล่วงหน้า (`update_hud = false`)
  - ย้ายคำสั่งการสลับไฮไลต์แท่นหิน, การเปลี่ยนข้อมูลการ์ด HUD, การเปลี่ยนแท็บ Act และเสียงกระทบแท่นหิน (`_play_sfx(sfx_click)`) ไปทำงานภายใน Event Callback `_jump_tween.finished` (จังหวะที่ตัวละครแตะถึงพื้นแท่นหินปลายทางอย่างสมบูรณ์เท่านั้น)

### 13.2 การปรับความเร็วและแอนิเมชันช่วงด่าน 15–16 พร้อมท่าชูมือขณะร่วงหล่น (15–16 Transition & Falling Pose)
- **ปัญหาเดิม:** ด่าน 15 (ยอดบันไดวน Act 1 ที่ `y = 1250`) และด่าน 16 (ใจกลางโถงทีม Act 2 ที่ `y = 560`) มีระยะห่างในแนวดิ่งมากถึง **690 พิกเซล** แต่เดิมใช้เวลาการกระโดดเพียง `0.72s` และกล้องเลื่อนเร็ว `0.48s` ทำให้การเคลื่อนที่เร็วเกินไป จนผู้เล่นมองไม่ทันเห็นแอนิเมชันท่าทางพิเศษ โดยเฉพาะตอนถอยหลังจาก 16 ลงมา 15 ที่ตัวละครต้องทำท่าตกลงมาพร้อมชูมือขึ้น (`vel_hold`)
- **การแก้ไข:**
  - ขยายระยะเวลาการเคลื่อนที่ข้ามชั้น 15 ➔ 16 และ 16 ➔ 15 เพิ่มขึ้นเป็น **`1.35s`** (จากเดิม `0.72s`)
  - ซิงค์ระยะเวลาการเลื่อนกล้องติดตาม (`_scroll_to_stage_idx`) ให้สัมพันธ์กันที่ **`1.30s`** ด้วย `Tween.TRANS_CUBIC` และ `Tween.EASE_OUT`
  - **ตอนถอยกลับ (16 ➔ 15):** ตัวละครจะเล่นท่า `vel_anim.play("hold")` (ตกลงมาจากฟากฟ้าพร้อมชูสองมือขึ้นสูง) ตลอดระยะเวลาการร่วงหล่น 1.35 วินาที พร้อมปรับวิถีโค้งพาราโบลา `peak_height = 25.0` ให้ตัวละครค่อย ๆ ร่วงดิ่งลงสู่แท่นหินอย่างชัดเจนเต็มตา ก่อนจะเปลี่ยนกลับเป็นท่ายืนหายใจปกติ (`breathe`) เมื่อลงสู่พื้น
  - **ตอนไต่ขึ้น (15 ➔ 16):** ตัวละครจะเล่นท่าตัวตรงสง่างาม `vel_anim.play("stand_straight")` ลอยขึ้นสู่โถงชั้น 2 อย่างนุ่มนวล

### 13.3 การล็อกขนาดคงที่ของแท็บใน Navbar เพื่อป้องกันอาการกระตุกขยับไปมา (Navbar Layout Stability & Zero Jitter)
- **ปัญหาเดิม:** เมื่อคลิกสลับแท็บ Act ในแถบ Navbar ส่วนหัว (`ActTabsHBox`) ทั้งกลุ่มปุ่มและข้อความเกิดการกระตุกขยับเยื้องซ้าย-ขวาไปมา เนื่องจาก:
  1. `ActTabsHBox` ถูกจัดวางอยู่กึ่งกลางระหว่าง `SpacerLeft` และ `SpacerRight` ซึ่งตั้งค่า `size_flags_horizontal = 3` (Auto-centering)
  2. เมื่อแท็บเป็น Active ระบบกำหนด Padding เพิ่ม `content_margin_left = 10.0`, `content_margin_right = 10.0` แต่แท็บ Inactive ไม่มี Padding ทำให้ความกว้างของปุ่มขยายจาก 80px เป็น 96px เมื่อถูกคลิก
  3. ข้อความแสดงความคืบหน้า (`ACT 1 · 0 / 15 LEVELS`, `ACT 2 · 0 / 5 LEVELS`, `ACT 3 · 0 / 20 LEVELS`) มีความยาวตัวอักษรไม่เท่ากัน และไม่ได้ล็อกความกว้างขั้นต่ำ ทำให้ขนาดรวมของ Container เปลี่ยนแปลงตลอดเวลา
- **การแก้ไข:**
  - ล็อกขนาดขั้นต่ำของปุ่มแท็บ `BtnAct1`, `BtnAct2`, `BtnAct3` เท่ากันทั้งหมดที่ `custom_minimum_size = Vector2(96, 44)`
  - ปรับขอบเขต Padding ของ StyleBox ทั้งสถานะ Active และ Inactive ให้เท่ากันที่แนวนอน `0.0` (ไม่มีการขยายขนาดเมื่อถูกคลิก)
  - ล็อกความกว้างของกรอบข้อความความคืบหน้า `ActProgressPanel` คงที่ที่ `custom_minimum_size = Vector2(200, 44)` พร้อมจัดข้อความกึ่งกลาง (`horizontal_alignment = 1`)
  - ล็อกความกว้างของปุ่มดำเนินต่อ `BtnFocusCurrent` คงที่ที่ `custom_minimum_size = Vector2(116, 44)`
  - **ผลลัพธ์:** ความกว้างรวมของแถบ `ActTabsHBox` ถูกล็อกคงที่อย่างถาวรที่ `670 px` ไม่ว่าจะคลิกสลับบทใด ปุ่มและข้อความจะคงตำแหน่งเดิมนิ่งสนิท 100% ไม่มีอาการกระตุกหรือขยับเยื้องไป-มาอีกต่อไป


## 14. สถาปัตยกรรมการปีนหอคอยโกธิคผ่านกำแพงอิฐและช่องเปิดประตูศิลา 8 ชั้น (Act 3 Gothic Tower Climbing Experience)

### 14.1 คอนเซปต์หลักและการเปลี่ยนผ่านจากตารางการ์ดสู่การปีนหอคอยโบราณ (Core Concept & Floor Architecture)
- **ปัญหาเดิม:** ผังด่าน Act 3 (ด่าน 21–40) ในระบบเดิมถูกบีบอัดให้อยู่ในรูปแบบการ์ดลอยลอยตาราง 5 คอลัมน์ x 4 แถว บนพื้นที่แนวดิ่งเพียง 270 พิกเซล (`y = 430` ถึง `160`) ทำให้การ์ดมีขนาดเล็กจิ๋ว ขาดความรู้สึกของความยิ่งใหญ่และความเป็นหอคอยโกธิค ไม่สอดคล้องกับธีมการไต่ยอดหอคอยโบราณ
- **การปฏิรูปใหม่:** เปลี่ยนผ่านสู่ประสบการณ์การปีนหอคอยโบราณอันยิ่งใหญ่ (Climb Through a Massive Ancient Gothic Tower)
  - สร้างกำแพงอิฐศิลาแนวนอน (Horizontal Brick Walls) ขวางกั้นแต่ละชั้นของหอคอย
  - ในแต่ละชั้นจะมีกำแพงอิฐทึบปิดกั้นทางขึ้น และมี **ช่องเปิด/ซุ้มประตูศิลา (Passage Opening)** กว้างพอให้ตัวละครเดินผ่านได้
  - ตัวละครและเส้นทางจะสามารถปีนขึ้นสู่ชั้นถัดไปได้ผ่านทางช่องเปิดนี้เท่านั้น ทำให้กำแพงอิฐทำหน้าที่เป็นอุปสรรคทางสายตาและกายภาพอย่างแท้จริง
  - บนยอดสูงสุดของหอคอย (Floor 8: The Summit Deck) ประดับด้วยแท่นบูชาศิลาโบราณ วงแหวนเวทมนตร์อักขระ Git สีทองอำพัน และเงาปรมาจารย์ Git ผู้สาบสูญ

### 14.2 โครงสร้างกำแพงอิฐโกธิคและช่องเปิดซุ้มประตูศิลา (`act3_brick_floors.gd`)
สร้าง Control Node พิเศษแบบ `@tool` ชื่อ `Act3BrickFloors` ทำหน้าที่เรนเดอร์กำแพงอิฐและซุ้มประตู 7 ชั้นด้วยโค้ดเวกเตอร์พิกเซลอาร์ตอันประณีต:
1. **เนื้อกำแพงอิฐ (Pixel-Art Brick Wall):**
   - ใช้พาเลตต์อิฐสีเทาถ่านเข้มและม่วงอมเทาหม่น (`BRICK_PALETTE` 7 เฉดสี) สลับแถวแบบก่อสลับก้อน (Running Bond)
   - ปูนก่อยึดสีดำขลับ (`MORTAR_COLOR = #0f1217`) พร้อมขอบแสงไฮไลต์บนซ้าย (`#596170`) และขอบเงาร่องลึกขวาล่าง (`#0a0d10`)
   - คานหินบัวบน (Top Gothic Coping Ledge) และคานหินบัวล่าง (Bottom Coping Trim) เสริมความมั่นคง
   - เงาทอดลึกใต้กำแพง (Deep Ambient Drop Shadow) ความสูง 24px โปร่งแสง 45%
2. **ช่องเปิดและซุ้มประตูศิลา (Passage Openings & Gothic Archways):**
   - กำแพงอิฐจะหยุดลงตรงช่องเปิดอย่างสมบูรณ์ ไม่มีการวาดอิฐทับช่องทางเดิน
   - ขนาบข้างด้วยเสาศิลาซุ้มประตู (Arch Pillar Posts) พร้อมบัวหัวเสา (Capital) และฐานเสา (Plinth)
   - คานหินครอบหัวซุ้มประตู (Arch Lintel Header) และยอดศิลาหัวซุ้มประตูตรงกลาง (Keystone Crest)
   - ลำแสงมนตราเรืองรองอบอุ่นสีทองอำพัน (`PASSAGE_BEAM_COLOR`, `PASSAGE_GLOW_COLOR`) ส่องผ่านช่องทางขึ้น
3. **ป้ายศิลาจารึกชื่อชั้นโบราณ (Gothic Floor Inscription Plaques):**
   - สลักชื่อชั้นสไตล์โรมันโกธิคบนแผ่นศิลาในฝั่งกำแพงที่กว้างกว่า:
     - `FLOOR I · THE INSPECTION DECK`
     - `FLOOR II · RESTORATION VAULT`
     - `FLOOR III · BRANCHING CLOISTER`
     - `FLOOR IV · GRAPH SANCTUARY`
     - `FLOOR V · BASTION OF MERGE`
     - `FLOOR VI · REMOTE ARCHIVES`
     - `FLOOR VII · THE CITADEL GATE`

### 14.4 ขนาดแท่นศิลาและเส้นทางการไต่ระดับ (Platform Sizes & Physical Path Connections)
